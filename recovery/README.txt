SFP ONU recovery (BPI-R4 + Huawei MA5671A в клетке SFP1/WAN)
=============================================================

Что делает этот образ
---------------------
Сервис sfp-recovery стартует на 99-м шаге загрузки и запускает
/usr/sbin/gpiouart в автономном режиме. Консоль модуля идёт по пинам клетки:
  pio69 (TX_FAULT, SFP пин 2)  <- TX модуля
  pio21 (RS0,      SFP пин 7)  -> RX модуля
Никаких проводов не нужно: модуль просто стоит в WAN-клетке.

Порядок действий
----------------
1. Загрузить роутер с этого образа. На USB-консоли роутера (ttyS0) появится
   строка "===== sfp-recovery start ...", результат selftest и дальше весь
   поток с консоли модуля (зеркало лога).
2. Если модуль ещё не вставлен — вставить. Если уже стоял — вынуть и вставить
   заново, чтобы утилита поймала его U-Boot (Ctrl+C шлётся каждые 20 мс).
3. Дальше всё само: U-Boot -> команды из cmds_uboot.txt -> boot -> Linux ->
   логин (root/admin123 и запасные) -> команды из cmds_linux.txt -> reboot.
   Каждая фаза выполняется один раз за сессию (--max-sessions 1).
4. Забрать /root/recovery/console.log (и вывод USB-консоли роутера).

Автоопределение полярности TX
-----------------------------
Если модуль печатает, но не реагирует на наш ввод (нет эха логина), после
двух попыток утилита инвертирует полярность TX и пишет об этом в лог:
  "### TX POLARITY FLIPPED -> invert_tx=1". Результат сохраняется в
/root/recovery/state и подхватывается при следующем старте.

Файлы (все в /root/recovery, редактируются на роутере через vi, без пересборки)
------------------------------------------------------------------------------
console.log      - полный лог с метками времени; строки "### ..." — события утилиты
cmds_uboot.txt   - команды для U-Boot модуля
cmds_linux.txt   - команды для Linux-консоли модуля
state            - выученная полярность TX (удалить, чтобы сбросить)
extra_args       - дополнительные аргументы gpiouart (например: --no-autoflip -i)
disable          - если файл существует, сервис не стартует

Ручной режим
------------
/etc/init.d/sfp-recovery stop
gpiouart selftest
gpiouart console            # интерактивно, Ctrl+] выход, Ctrl+C уходит в модуль
gpiouart console -i         # с инвертированным TX
gpiouart auto --log /tmp/x.log --cmds-uboot /root/recovery/cmds_uboot.txt -t 300

Что смотреть в логе
-------------------
- selftest: "TX read-back ... PASS" — площадка pio21 переключается;
  "RX ... ACTIVITY" — модуль передаёт.
- "stats: rx_ok=N rx_fe=M glitch=K" — M и K должны быть << N.
- "TX CONFIRMED" — модуль нас слышит; "TX POLARITY FLIPPED" — сработала инверсия.
